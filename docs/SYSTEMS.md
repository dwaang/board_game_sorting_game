# SYSTEMS.md

# Existing Project Architecture Audit

> Шаблон для первого аудита проекта.
> Codex должен заполнить его после изучения реального проекта.
> Не придумывать отсутствующую архитектуру.

## 1. Структура проекта

Описать:
- основную игровую сцену;
- сцену игрока;
- UI;
- autoload;
- addons;
- систему сохранений;
- Steam/multiplayer;
- дерево навыков;
- систему взаимодействия;
- базовые классы и Resources.

## 2. Autoload

Для каждого:
- имя;
- путь к скрипту;
- ответственность;
- публичный API;
- нужно ли переиспользовать в этой игре.

## 3. Система сохранений

Описать:
- точку входа;
- формат;
- слоты;
- сериализацию;
- регистрацию игровых данных;
- миграции/версии, если есть;
- куда интегрировать состояние магазина.

Будущее состояние:
- перемещённые коробки;
- установленные коробки;
- флаг первой награды;
- время последней засчитанной установки;
- завершённые серии;
- завершённые франшизы;
- очки навыков;
- дерево навыков.

## 4. Дерево навыков

Описать:
- формат данных;
- открытие навыков;
- стоимость;
- пассивные навыки;
- активные навыки;
- UI;
- сохранение;
- будущую общую кооперативную прогрессию.

## 5. Steam / Multiplayer

Описать:
- addon/plugin;
- transport;
- lobby/invite;
- host/join;
- peer IDs;
- RPC;
- authority/ownership;
- voice, если уже есть;
- точки интеграции игровых событий.

## 6. Player Controller

Описать:
- движение;
- камеру;
- input;
- interact;
- анимации;
- тип physics body;
- как интегрировать стопку коробок.

## 7. Система взаимодействия

Описать:
- интерфейс/base class интерактивных объектов;
- raycast/shape cast;
- подсказки;
- ownership;
- точки интеграции Box, ShelfSlot, Cart и player-to-player interaction.

## 8. UI

Описать:
- HUD;
- уведомления;
- Skill Tree UI;
- меню;
- multiplayer markers;
- переиспользуемые компоненты.

## 9. Рекомендуемые точки интеграции

После аудита указать реальные существующие классы/скрипты для:
- BoardGameBox runtime state;
- статических данных контента;
- Carry Stack;
- ShelfSlot;
- проверки установки;
- наград;
- завершения серии;
- завершения франшизы;
- активных cooldown;
- сохранения;
- сетевой синхронизации.

## 10. Риски / конфликты

Только реальные проблемы, найденные в проекте.

Для каждой:
- текущее поведение;
- требование GDD;
- минимальное рекомендуемое изменение.

## 11. На этом этапе не реализовывать

Первый проход `SYSTEMS.md` — только аудит.
